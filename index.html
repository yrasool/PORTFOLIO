I start by understanding the system, the failure modes, the data path, and the smallest useful change that can be built, reviewed, and validated. From there, I like to define requirements, edge cases, deployment assumptions, and checks that make the next iteration safer instead of heavier.

Artifacts

Issues, requirements notes, acceptance criteria, data assumptions, test notes, and clear next steps for implementation.

Collaboration

Scrum-style working sessions, shared interpretation of the problem, quick reviews with engineers, and practical adjustments when new constraints appear.

Validation

Observable outcomes, edge-case checks, query sanity checks, release-readiness notes, and enough structure to support continuous delivery.
